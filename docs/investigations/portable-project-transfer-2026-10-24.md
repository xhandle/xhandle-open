# Complete code architecture project archives

Implemented from `docs/codex-prompts/portable-code-architecture-project.md`.

Code-Based Architecture → actions → Export complete project (also dashboard Export Project) creates a `.xhproject` archive. After preparation, click **Save Complete Project File**. On the destination use **Import project file**, then reload. Both installations must include this implementation; older JSON/CSV imports remain supported but do not gain missing historical checkpoints.

Stop running analyses, save edits, and close other xHandle tabs before export/import. Architecture and requirements writes are drained; visible requirement edits are flushed before export. Unsaved architecture publication/hazard/requirement failures prevent a misleading successful export. The archive contains private project/source data and should be handled accordingly. Account credentials and OS folder permissions are not transferred.

The archive copies project-owned IndexedDB records and local settings, including chunked architecture publications/history/checkpoints, functional request responses, source indexes for connected repositories/snapshots, hazard runs/metadata/generation checkpoints, assurance rows, review/remediation dependencies, project graph and owned traceability/evidence records. Stored IDs, fingerprints and chunk references are retained. It uses record-wise encoding and a checksum, with bounded file reads on import; it never hydrates all architecture chunks into one export object. Progress percentages during export are storage-stage estimates; import percentages represent archive bytes processed in each pass.

Requirements derivation now checkpoints successful model responses under project/repository/kind and exact prompt/provider/model/effort. **Continue saved derivation work** is enabled by default. Uncheck it for fresh generation. Failed or unusable responses are not cached. Existing normalization/traceability behavior still runs on cached responses. Responses from runs before this implementation cannot be reconstructed if they were never saved.

Import validates the archive before writing, rejects an existing project ID and conflicting stored records, merges unrelated destination projects, and publishes the project entry last. It rolls back newly inserted records and local changes on a caught failure or cancellation. This is not a single transaction across databases; process termination during import can leave unpublished records. An identical archive can reuse identical records on retry. Other tabs must be closed to avoid concurrent mutations. Missing/blocked storage errors are surfaced.

Resume conditions: use the same source revision and analysis inputs/settings. GitHub access and AI credentials must be configured in the destination. Local folders must be reconnected to the same contents. External files that were never saved in the source index are not embedded; the original repository/folder supplies them. Compatibility checks remain active so different inputs are not mislabeled as completed. The archive transfers saved work, not an executing network request.
