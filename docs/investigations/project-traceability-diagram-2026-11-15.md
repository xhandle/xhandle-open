# Project traceability directed graph

The systems engineering project’s Traceability tab now opens a Diagram view alongside the existing Table view. It uses the same worker-loaded graph and the same recorded directions and relationship types. It does not infer links, modify a traceability profile, approve evidence, or write graph edits.

The artifact overview condenses current object-to-object citations into directed artifact-to-artifact links, retaining their original relationship IDs and counts. Supporting sources can be grouped for readability. Historical source revisions remain distinct from current artifacts, and unresolved references remain visible. Selecting a node or edge exposes the original relationships in a paged inspector; artifacts, objects and evidence open through existing navigation and source readers. Requirements with blank titles use bounded requirement text as their graph label.

The Objects level offers artifact selection, text search and pages of 20 objects plus their immediate incoming/outgoing neighbors. Layout/rendering is bounded to 80 nodes and 240 edges, with an explicit notice when a view is partial. The full trace register is retained. This prevents a large hazard-analysis inventory from creating tens of thousands of ReactFlow nodes. The canvas provides pan, zoom, fit-to-view, arrowheads and selection highlighting. Long graphs start at a readable zoom with a navigable minimap; Fit diagram explicitly fits the entire displayed graph. Object cards identify their owning artifact so copied requirements can be distinguished. The view is read-only.

## Artifact icons and routed connections

The graph now represents artifacts with distinct Lucide symbols and labels instead of rectangular cards. All supported engineering document types have separate symbols; functional/code architecture, source projects, saved evidence and object references also remain identifiable. Selection highlights the icon, and existing open/inspect actions are retained.

The bounded graph is laid out using the existing ELK dependency with spline edge routing and reserved rectangles for each icon, title, type label and gap badge. Edge labels participate in layout. Connections enter or leave only the icon's horizontal terminal lane, with clearance around the glyph; intermediate curves route around other items. Historical and parallel relationships, cycles and self-loops keep their original directions and identities. Asynchronous layout completion is ignored after a view change; a failed layout provides a retry action.
