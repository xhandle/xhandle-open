# Traceability role-binding suggestions

The **Suggest role bindings from this project** action could appear inert for two reasons. It had no visible result when automatic setup had already selected the matches. Its ownership matcher also compared artifact metadata against the wrong project identity: systems engineering member metadata names the engineering project, while the underlying Projects/Code-Based Architecture owners are stored in the document configuration. A matrix configuration has no `id`, so comparing absent IDs could additionally include unrelated standalone documents.

The corrected matcher distinguishes the exact engineering-project scope from an underlying workspace project. Engineering-project matrices suggest only their own members. Underlying Projects/Code-Based Architecture matrices match exact workspace/project pairs in artifact metadata or recorded source owners, including secondary owners. Missing identities, deleted documents, shared folders and equal IDs in a different workspace do not qualify. Changing the owning project during matrix creation also changes the suggestion scope.

The button now refreshes the source catalog, adds suggested bindings while retaining manual selections, expands the matching roles and reports matches and additions. Repeated clicks explicitly report that the suggestions are already selected. No matches produce guidance to create matching artifacts or select sources manually. Suggestions are disabled until a project/profile is available; pending requests are invalidated after a scope/profile change or unmount.

Regression coverage includes grouped documents, standalone documents, secondary code-project owners, absent IDs, unrelated projects, exact program configuration, manual selections, sources created after opening the dialog, repeated clicks, empty matches and switching the owning project before creating a matrix.
