# Saved report library and output continuation

The user reported a provider output-limit failure during report generation and requested a compact library of generated reports. Previously the current report occupied one project-state field, a new result replaced it, diagram images were transient, and a long prose response restarted rather than continuing.

## Behavior

- Reports has a compact per-project library with titles, types, dates, search, Open, and confirmed Delete. Each generation gets a separate immutable record; older versions remain available.
- Report documents and their diagram snapshots live in `xhandle-generated-reports` IndexedDB. A separate indexed metadata store supplies the list; bodies and images are loaded for the opened report. The library loads in the Reports or project Reporting area, not during unrelated diagram/table work.
- Reopening a saved report uses its own image snapshot rather than the project's current canvas. The existing latest report is adopted into the library once. Previously overwritten reports cannot be reconstructed. An available image already displayed with a legacy report can accompany that first adoption; missing historical images cannot be recovered.
- The small project cache retains the selected report identifier, latest text, and display metadata for compatibility. It excludes full analysis/agent state and image data. Report history and images are included in full workspace backup/restore. Existing analysis-only project archives do not transfer the report library.
- Prose generation can continue a length-limited answer using its partial text in the conversation. Planning, chunk summaries, and audit JSON still require complete validated objects and are never concatenated as fragments. Final writing and continuation are identified in activity progress.
- Continuations are bounded to four output segments per prose request, with bounded per-segment retries and output budgets. Reasoning GPT-5/6 and o-series models may grow to 32,768 output tokens; other paths retain a 16,384-token retry ceiling. User provider/model/effort selection is preserved. Provider capability, refusal, input limits, and extreme reasoning consumption can still prevent completion.
- A final-writing interruption retains available text as an explicitly incomplete saved draft. Earlier completed reports are preserved when a new attempt fails. Storage failure keeps the current text available with an unsaved warning; it does not claim successful persistence. Error logging excludes draft text.
- Each generation owns its summary state, preventing simultaneous or project-switched runs from sharing mutable findings. Late completion saves under the original project and cannot replace another project's active report.
- Whole-report Delete removes the document and image together. A minimal identifier-only deletion marker prevents an old project-cache copy from resurrecting it; the marker contains no title, report text, or image. Permanent project cleanup removes library records and markers and waits for/blocks pending report writes. Backup and Storage settings recognize the new database.

## Verification

The combined regression run passed 184 tests across 14 frontend suites, covering generation, continuation, library UI/storage, report images, system/subsystem editing, settings, backup, logical storage, and project deletion. A subsequent deletion-race hardening run passed all 18 library UI/storage tests, including one additional case preventing refresh from recreating a deleted report. There are 185 distinct frontend cases across these runs. The actual-parser checks passed 18 tests, and backend provider compatibility passed 27 tests.

Storage tests verify immutable versions, image retention, metadata-only lists, project isolation, idempotent/concurrent legacy adoption, atomic rollback on a failed write, incomplete status, unavailable storage, deletion markers, and full backup download/restore. Project-cleanup tests verify removal of both library stores while preserving other projects. UI tests cover opening/search, compact-pointer hydration, no reads outside Reports, late reads after project switching, deletion confirmation, and preserving unsaved text when migration fails. Generation tests cover bounded automatic continuation, retention of partial text on a subsequent network failure, structured-response boundaries, and independent concurrent runs.

An isolated Electron 45 fixture saved two complete versions and one draft with synthetic image snapshots, then exited. A fresh Electron process reopened the same temporary profile and verified all three versions, draft status, metadata-only listing, project isolation, and successful decoding of the saved image. HTTP/HTTPS requests were blocked. No customer data or paid AI provider calls were used.

Focused lint and whitespace checks passed with existing App warnings. The final optimized production build passed with existing repository warnings. Successful generation with the user's selected live provider remains an acceptance check; synthetic tests cannot guarantee every long report completes within its provider's limits. All changes remain local and unpublished, and the distributed 0.2.14 release is unchanged.
