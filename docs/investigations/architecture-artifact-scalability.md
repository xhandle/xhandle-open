# Architecture artifact scalability and abstraction-aware drafting

## Findings

- Background maintenance recaptured every artifact's sources every 30 seconds and after artifact checkpoint/freshness writes. A large code repository was therefore rebuilt repeatedly even when its sources had not changed.
- Opening an artifact loaded all project member revisions and jobs. The document view also prepared the native requirements and trace projections. Proposal comparisons and evidence lists mounted their hidden contents.
- Code diagram layout received the entire graph. Viewport culling alone did not bound layout or the inspector's option count. Artifacts also used a generic renderer instead of the source Code-Based Architecture canvas, losing its native hierarchy and presentation.
- The model-facing citation projection expanded every aggregate's members and supporting implementation relationships. Selecting Subsystem, CSCI or CSC changed the diagram, but its AI context could still contain the complete function/call inventory. Functional rows could embed the same implementation provenance repeatedly.

## Changes

- Code artifacts now reuse `LiteSummaryDiagramReactFlowGitHub`, including native hierarchy containers, connections, abstraction styling and saved routing. CSU presents functions inside software units, matching the source workspace; Subsystem/CSCI/CSC use compact aggregate rows without expanding the full implementation. Saved positions, notes and comments are captured with the source revision; rendering and export are read-only and isolated from source storage. Older snapshots without saved presentation use the same renderer with its normal layout.
- Subsystem, CSCI and CSC diagrams remain on one canvas up to 500 aggregate elements and 1,000 aggregate relationships. Detailed and larger code graphs use presentation-only views of at most 120 source nodes and 60 explicit relationships (the native renderer adds the corresponding hierarchy containers). Search reaches elements across all views; all saved nodes, boundaries and relationships remain available with their original IDs and evidence. Small diagrams and the native Projects diagram renderer retain their presentation.
- CSC parity correction: capture previously treated every relationship-row allocation as another allocation of each endpoint. Shared functions therefore became synthetic “Unallocated” groups, even though the source canvas resolved them to named components. Both paths now use `computeDiagramArchitectureByNode`: first row-level allocation, overridden by the explicit allocation on the last endpoint occurrence. The display allocation is stored separately from all original recorded allocations and relationship rows. Aggregate identity uses the same Subsystem → CSCI → CSC → CSU path as the native renderer. Snapshot projection version 2 identifies this behavior; earlier revisions remain immutable and show an update instruction.
- The fallback layout worker receives topology and display labels capped at 240 characters. The native code canvas receives the bounded presentation view. Complete labels and implementation evidence remain in the saved snapshot and inspector.
- Native display projections remain stable when the same saved revision is reloaded. A new source revision remounts the canvas, preventing metadata refreshes from resetting positions after layout and causing overlapping nodes.
- The diagram download explicitly exports the current view for a large graph. Word, PDF and Markdown document exports include every view. Interactive PNG, Word, PDF and Markdown exports render each view using the same native canvas as the on-screen artifact.
- Document view skips requirements projection. Full project traces load only when requested. Proposal arrays are memoized; comparisons and implementation evidence lists mount only when expanded and display 50 entries per page.
- Artifact writes no longer trigger source scans. Source-change events remain debounced; periodic fallback is five minutes and hidden tabs defer scanning. Generation and acceptance still check live source hashes independently. Identical configurations share one hash request within a sweep.
- Node/allocation aggregation accumulates sets/maps once rather than repeatedly rebuilding and sorting previously collected entries. Snapshot content and canonical hashes retain the same semantics.
- Subsystem, CSCI and CSC AI context contains selected-level descriptions, boundaries, endpoints and implementation counts, without expanding lower-level member/file/call inventories. Selected-level descriptions and separate requirements remain intact.
- CSU and Functional context includes more detailed implementation examples, with explicit additional-item counts, and excludes repeated raw provenance. Examples are explicitly identified as non-exhaustive; original supporting records remain in the immutable source manifest. Functional exchange descriptions, kind and significance are retained.
- Request guidance describes the selected abstraction and discourages implementation inventories. Higher-level drafting targets up to eight concise objects per section with a smaller initial output allowance; detailed drafting targets twelve. Retry, validation, citation and run budgets remain enforced.
- Evidence-review version is advanced so a partially saved review made under the older context policy cannot be silently reused under a different partition. Existing accepted documents remain intact. A fresh update applies the new policy throughout an existing draft.

## Validation

- Artifact and shared-renderer regression suites cover native editing/traceability, generation recovery, source freshness, citations, exports and architecture capture. Native renderer tests verify restored absolute coordinates and no source-storage writes; adapter tests verify CSU coverage and CSC source mappings. A shared-function, cross-subsystem fixture renders both the original rows and the captured CSC artifact through the real native component and compares group IDs, node positions and connection IDs while checking complete retention of original relationships.
- A 10,000-relationship fixture verifies bounded page sizes, complete endpoint/relationship coverage, unchanged evidence references and navigation to distant/isolated elements.
- Component tests verify bounded native renderer inputs and inspector options, cross-view search, lazy evidence pagination and no requirements projection in document view.
- Context tests use aggregates with 10,000 implementation members and relationships: Subsystem/CSCI/CSC remain below 2,000 serialized context characters per fixture while retaining selected-level constraints and canonical citations. CSU/Functional examples remain bounded and report omitted example counts.
- The same synthetic repository needs no extra evidence review at CSC level, while its Functional representation spans more than five evidence groups. This measures context reduction, not a live provider latency guarantee.
- Production worker diagnostics retained 2,000 implementation relationships and 32,000,100 evidence characters. Capture took 4.35 seconds and freshness hashing 4.92 seconds, with maximum main-thread heartbeat gaps of 24 ms and 22 ms respectively in the synthetic browser fixture.
- Production browser diagnostics verify non-overlapping native CSU nodes, architecture acceptance without AI requests, Word/PDF exports and preserved requirements views. A 3,001-element/4,500-relationship Functional fixture verifies bounded rendering and cross-view search, including the selected distant element actually appearing inside the canvas; the final production run measured a maximum heartbeat gap of 51 ms.
- Production build succeeds with existing repository warnings. No live AI-provider timing claim is made.

## Limits

Complete source snapshots still consume storage and must be captured and checked. These changes bound display and drafting expansion; they do not make repository capture independent of source size. Native display defaults and allocation precedence reproduce the source canvas, not new verified ownership claims; original allocation evidence remains unchanged. Runtime also depends on the actual number of selected-level elements, document scope and provider latency. No user repository data is modified by the synthetic diagnostics. Existing saved artifacts need Generate update to capture the corrected grouping; accepted revisions are not rewritten.
