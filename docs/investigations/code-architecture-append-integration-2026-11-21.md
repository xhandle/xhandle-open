# Append: source integration across analysis batches

Published after review in [Desktop 0.2.20](desktop-0.2.20-publication-2026-11-21.md). That record supersedes preparation/unpublished status below and identifies the frozen source, final requested UI and release evidence.

Prompt executed: [append-code-architecture-integration.md](../codex-prompts/append-code-architecture-integration.md). This extends the uncommitted Replace/Append workflow; no commit, push, installer, or update-feed publication is included.

## Result

Append now includes a separate connection-review phase after extraction and before publication. It revisits verified source from every earlier analyzed file and the newly selected files, including earlier files whose original run produced no relationships. It searches both earlier → new and new → earlier directions. Replace and first analysis retain their existing behavior; selecting only previously analyzed files still makes no model requests.

The phase indexes actual source functions, references, exported binding keys, callback/channel registrations, and route literals. Exact relative module paths and named/namespace aliases guide resolution; imports above the repository root, bare JavaScript packages without a verified mapping, and unrelated path literals cannot masquerade as local module imports. Multiline import declarations retain their alias evidence across source windows. Quoted C includes resolve relative to their source file. Uppercase extensions retain their language family and exact path identity.

Candidate discovery uses indexed lookups rather than an all-pairs model scan. Ambiguous short names remain unresolved unless an exact import resolves them. Shared, explicitly registered channels can have multiple receivers. Requests page source windows, caller units, import evidence, and target definition/registration frames; long source or minified lines are not silently cut off. The source cache holds at most four records, and immutable saved indexes are reused after checking their text digests. Missing indexes are reacquired through the existing pinned GitHub/local source adapters, including rate-limit waits and cancellation.

## Evidence, identity and recovery

- Each accepted proposal has exact source/destination file and symbol identities, checked source citations, source digests, and a stable relationship identity. Cross-language bindings require concrete binding evidence and a caller-side invocation. Callback and message/route links require the corresponding registration or channel evidence. Comments, plain string/template text, regex literals, local shadowing, unknown receivers, ambiguous callers and incorrect citations cannot establish a link.
- These are explicitly **source-cited model proposals requiring engineering review**, with `supported: false`; they do not claim syntax-complete or proven runtime dispatch. Integration proposals may enter the diagram and hazard source set without weakening the ordinary Python unmatched-proposal policy or nonproduction-call exclusions.
- Previously published rows, history, analyst edits, eligibility decisions, trace IDs, immutable evidence and valid functional identities are retained. New detailed links reuse current endpoint node IDs rather than historical IDs. Distinct channel keys retain separate relationship identities; duplicates already represented by earlier or current extraction reuse the existing relationship. Functional models merge through exact endpoints, and the enlarged source snapshot makes older hazard results stale while retaining their data.
- Integration checkpoints are distinct from completed file extraction. Task identities include version, exact source digests and the evidence prompt, within the existing scoped/base-checked analysis checkpoint. Successful responses resume without repeated requests and are validated again against source. A changed provider or source, cancellation, malformed response, storage failure, edit/deletion or competing publication cannot publish a partially completed pass over the current architecture.
- The completed run manifest retains accepted integration evidence and per-file rejected/unresolved audit entries, including proof for discoveries already represented in the graph. Lightweight coverage is persisted in metadata and displayed under **Connections between analysis batches**. The found count describes accepted discoveries before deduplication, rather than asserting that every discovery added a new graph row.
- Relationship reconciliation now indexes candidates rather than scanning every previous row for each incoming row. A 25,000-row baseline plus 3,000 new rows verifies retained IDs and unique new row references.
