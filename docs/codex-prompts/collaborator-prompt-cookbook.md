# Bring the Prompt Cookbook into Collaborator

Implement this prompt in xHandle. Preserve existing uncommitted dark-mode work, the original logo, drafts, attachments, provider controls, voice controls and analysis behavior. Do not commit, push or publish an app update.

Make Prompt Cookbook available from Collaborator's existing + menu in both docked and full-screen layouts. Reuse one structured catalog for the current README examples and the new panel; retain all existing recipes and their descriptions. Include searchable browsing by task/category, a clear statement of what each recipe does, an editable prompt preview, and a Use prompt action. Opening, searching, closing, switching tabs and provider failures must preserve the composer draft and attachments. Use prompt must add to the existing draft and never submit or mutate workspace records.

Add Help me write a prompt: users describe the desired outcome, explicitly request a suggestion, and receive a cookbook-based prompt tailored to bounded current workspace metadata. Use the existing provider/model/effort and chat transport. Do not read full workspace contents, index files, call a provider while browsing, execute suggested tasks, invent unsupported capabilities or present prompt suggestions as completed engineering work. The helper may ask one focused clarification or explain that the task belongs in an existing app control. Validate responses, reject unknown recipes and malformed/oversized results, support cancellation, discard stale responses and handle errors without losing text. Suggestions remain editable and must be reviewed before normal Send.

Support accessible keyboard navigation, Escape, focus containment/restoration, narrow viewports and the current light/dark theme. Provide a composer-scoped Cmd/Ctrl+Alt+P shortcut and show it beside the cookbook action; avoid a global shortcut that steals unrelated application input. Keep any unrelated voice instructions intact.

Add meaningful catalog/protocol/component/integration tests and a production Electron harness scenario for both Collaborator layouts, draft/attachment preservation, AI success/failure/cancellation, unsupported requests, keyboard interactions and appearance. Use synthetic workspace data and controlled provider responses. Run adjacent tests and the appropriate Electron harness checks, inspect actual UI, and document the result and limits. Do not make guarantees about the correctness of model answers merely because a recommended prompt is used.
