Implemented compact SHA-256 cache identities where Web Crypto is available, with at most 96 clean entries retained. Dirty entries remain protected. Asynchronous identity calculation is serialized in write-call order. Existing durable checkpoint digests and scope versions are unchanged, so existing saved checkpoints remain reusable. Environments without Web Crypto retain a bounded clean JSON-key cache; the existing durable checkpoint backend already requires Web Crypto.

The runner now saves a lightweight incomplete recovery record before provider work, using the same attempt ID for final results. Startup's existing latest-run lookup can discover this record and offer Continue. A prior completed run remains intact with the new attempt stored alongside it. The record does not copy the architecture or generate an empty full table. It is not published to the live UI as a failure while generation is active. Final assembly reuses the existing source map instead of rebuilding compact source arrays twice.

Validation: a synthetic run through the actual cache processed 26,278 checkpoint entries with 10,000 evidence characters each. After successful writes, 96 clean entries remained, zero dirty entries, and 6,144 key characters. This measures cache retention, not total browser heap. Added tests cover clean-cache eviction with pending-write protection, startup lookup while provider work is unfinished, and final replacement of the recovery record. Existing tests cover checkpoint reuse, storage failures, ordering and cancellation.

Limitations: no live Safari heap profile or paid full architecture run was performed. Unsaved dirty results intentionally remain in memory if storage fails. Previously interrupted runs without a manifest are not retroactively labeled by this change, although matching row checkpoints can still be reused by a non-regenerate run. Page reload still terminates active execution; persistent storage must succeed for recovery. No commit or push performed.
