# Speed up Functional generation

Review and fix the shared Functional postprocessor used by GitHub, local and existing/imported code architecture projects. The current implementation serializes independent model requests and repeatedly scans all annotations during consolidation.

Use bounded concurrency for independent callers and consolidation batches, retaining sequential descriptor establishment within a caller. Keep request sizes, validation, retry/subdivision and full source coverage. Index consolidation relationships rather than scanning the full model per batch. Reuse an already-current validated model for automatic processing; explicit Regenerate must still request a fresh model. Make concurrent completion deterministic in source mapping and grouping order. On cancellation or terminal failure stop queued work, abort in-flight requests and never publish a partial model. Preserve provider error semantics and existing hazard/source traceability. Do not remove evidence, weaken abstraction, hard-code repository rules, or run paid/customer analyses to test speed.

Add tests for concurrency bounds, out-of-order completion, deterministic equivalence to sequential execution, cancellation/terminal failure, cache reuse and explicit regeneration. Benchmark synthetic delayed requests with the same rows and outputs under sequential and bounded parallel execution. Run functional/hazard/navigation/downstream regression tests and a production build. Report measured gains and remaining limits without promising fixed real-provider timings. Do not commit or push.
