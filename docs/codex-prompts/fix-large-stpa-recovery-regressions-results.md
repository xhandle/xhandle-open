Implemented bounded waits for initial, error-recovery and final saves. Initial persistence observes cancellation immediately; each storage wait otherwise has a 1.5-second deadline. Timing out does not cancel or replace the underlying writer. Existing per-record storage queues preserve write ordering. If storage remains blocked, completed results return in memory with save-pending status rather than blocking behind the manifest indefinitely. Late rejection is observed.

Recovery manifests now retain a compact identity sheet for user-owned rows, along with archived preprocessing and organization context identity. Normalization preserves the sheet, and preprocessing restoration uses it when a full Summary is absent. Missing identity data raises an explicit error instead of silently discarding user edits. Identity records contain matching columns and IDs, not narrative evidence.

New tests reproduce never-settling initial/final storage and prompt cancellation, and serialize/reload a manifest from an incomplete run with an explicit user exclusion. The resumed run preserves that exclusion and sends six applicable candidates rather than seven. Storage remains required for durable recovery; returning completed in-memory results does not imply they have been persisted. No commit or push performed.
