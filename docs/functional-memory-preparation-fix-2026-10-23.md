# Functional decomposition preparation window

Offer is reported to have been running Functional decomposition after CSU analysis. The earlier hazard-analysis review is not a diagnosis of that operation. This change targets the active `processResumableFunctionalModel` → `processFunctionalModel` → `createFunctionalRequestRuntime` path.

The runtime previously advertised 32 logical workers while permitting four network requests. Logical workers build prompts and read durable checkpoints before entering the network queue, retaining ahead-of-network work. It now advertises eight logical workers. Network concurrency stays at four; prompt rules, validators, relationship limits, analysis stages, checkpoint format, and source coverage are unchanged. Smaller ready queues can change which callers are packed together and can affect throughput; no speed improvement is claimed. Real provider output is nondeterministic, so identical output is established only for the deterministic test fixtures.

Added a 120-caller integration regression that delays checkpoint reads, checks at most eight simultaneous reads, and compares both complete model rows and derived functional rows with the existing unbatched baseline. The test failed on the old code with 32 concurrent reads and passes after the limit change. Existing network-concurrency, packing, semantic validation, checkpoint resume, transport recovery, and cancellation tests continue to pass: **105 tests across five suites**.

This is a targeted reduction of in-flight preparation, not an overall heap-byte bound or a demonstrated fix for a specific browser crash. It does not change existing CSU results or publish a desktop update.
